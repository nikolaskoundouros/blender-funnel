## Pipeline

```
face video (owner's phone, tripod)
  -> tools/face_track.py        own venv: mediapipe 1.2.3 + libEGL/GLES (survey section 1)
       per frame: 51 blendshape scores (+ tongueOut = 0), head yaw/pitch/roll/translation
       from the 4x4 transform, timestamps from the container
  -> CSV in Live Link Face channel order (so Faceit-style tools and ours read the same file)
  -> recipes/face_anim.py       inside bpy
       add_faceunit_keys(character): 52 shape keys on body and every fitted proxy
       (eyes, brows, lashes, teeth, tongue, clothes near the neck), values 0
       apply_track(character, csv, neutral_frame, gains, smoothing): per-channel neutral
       offset and gain, One-Euro smoothing, keyframes on shape keys; head channels onto
       neck/head bones (split between them), relative to the neutral frame
  -> render, then track the render again and compare curves (verification)
```

## Steps, each with its check

| Step | Builds | Check (number recorded) | Needs owner? |
|---|---|---|---|
| P1 (done) | `recipes/face_anim.add_faceunit_keys` | Every unit at 1.0 via shape key equals the static morph of F3: max vertex error < 0.1 mm on body and each proxy; two units at 0.5 each match the static sum (F6) | No |
| P2 (done) | `tools/face_track.py` + venv recipe | Response matrix: render each of the 52 units alone (240x240, P1 keys), track the render: the matching channel must be the highest score for at least 40 of 51; settles F5 (left/right) | No |
| P3 (skipped: P5 with a real clip done instead) | Round trip on synthetic motion | Key a 4 s sequence of units with known curves, render 96 frames at 240x240, track, Pearson r and lag per channel against the keyed curves; report channels with r < 0.7 | No |
| P4 (done, as `apply_curves`) | `recipes/face_anim.apply_track` | Apply P3's tracked CSV back onto the character; landmark check independent of the blendshape model: inner-lip gap / face width, source vs result, per frame | No |
| P5 (done) | Real face clip (owner has none; CC BY-SA Wikitongues clip used) | Same as P3/P4 with the owner's clip as source; Whisper word times from the owner's analyzer against jawOpen peaks for lip-sync timing | Yes: a clip |
| P6 (head done; eyes via eyeLook units, F7) | Head and eyes | Head yaw/pitch/roll from source and render, degrees per frame; eyes via eyeLook units first, `eye.L/R` bones if the morph looks wrong | Yes (P5 clip) |

Cost on this machine: tracking about 10 ms per frame; P2 is 52 renders (about 2 s each at
16 samples), P3 96 renders. All within the 30-minute limit.

## Risks carried over from the survey

Jitter on subtle channels (mouthRoll, mouthPress, mouthClose); no tongueOut from MediaPipe;
eyeLook units move eye helpers by translation (may need bones); camera-relative head pose
when the phone is handheld; Faceunits jawOpen moves teeth and tongue helpers, so the teeth
and tongue proxies need the same keys (P1 covers it).
